See what your coding agents did, project by project.

trail finds the session logs your agents leave on your machine, files each one under the project it ran in, and shows the transcript next to the changes it made.

Each project is the folder a session ran in: its git repository, or the folder itself when it isn't one.

Download for macOS & Linux
$ brew install veluribharath/tap/trail

One static binary. Read-only. Nothing leaves your machine.

Every session starts with a trace.

One tick per step: prompts tall, edits amber, failures red. You can read the shape of a session before you read a word of it, then drag across the strip to move through the transcript.

Everything an agent did, in one place.

Filed by folder

Sessions are grouped under the git repository they ran in. A session in a linked worktree lands under the main repo, labelled with its worktree and branch.

Transcript beside its diffs

Click an edit in the transcript to jump to its diff. Click a diff to jump back to the step that made it. Each diff is the exact before and after the agent sent. Filter to just the conversation, or only edits and failures. Bookmark the step that matters and leave yourself a note.

Commits that landed

The Commits tab lists what reached git while the session ran, from 10 minutes before to 2 hours after, with the commits that touch the agent's files first.

See the patterns

Stats show sessions per project over time, the files agents edit most, and how often each tool call fails, across every agent. Narrow them to one project, or print them with trail -stats 30.

Share it, or pick it up

Export a session as one HTML file that opens in any browser, offline, to attach to a pull request or a bug. Or copy its resume command and carry on in Claude Code, Codex, OpenCode, Gemini CLI or Kiro CLI.

Your transcripts stay yours.

Session logs hold prompts, file contents, command output and often secrets. trail is built so none of that goes anywhere.

  • Read-only. It reads agent storage and never writes to it. Your notes and bookmarks go in a file of trail's own, readable only by you. An export is saved only where you choose, and the file can't load or send anything.
  • Offline. The UI is embedded in the binary, fonts included. Nothing loads from the network.
  • Local. It listens on 127.0.0.1 by default and only runs git on your machine.
  • No dependencies. One static Go binary, built from the standard library.

Works with the agents you already use.

Up and running in a minute.

With Homebrew

On macOS. Updates come with brew upgrade, and there's no quarantine step.

brew install veluribharath/tap/trail
trail -open

Download a release

Builds for macOS (Apple Silicon and Intel) and Linux (x86_64 and ARM64) on the Releases page.

tar -xzf trail_*_darwin_arm64.tar.gz
xattr -d com.apple.quarantine ./trail  # macOS
./trail -open

With Go 1.24+

Installs the latest tagged version into your Go bin directory. To build from a clone instead, run make build.

go install github.com/veluribharath/trail@latest
trail -open

Run it

./trail          # http://127.0.0.1:7878
./trail -open    # and open the browser
./trail -list    # print sessions by folder and exit
./trail -export c1 -o session.html  # one session as an offline page
./trail -stats 30  # the last 30 days in numbers

On a remote dev box, run ./trail -host 0.0.0.0 on a network you trust, or tunnel the port over SSH.
